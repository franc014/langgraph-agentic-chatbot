# same graph — add checkpointer
graph = StateGraph(ChatState)
graph.add_node('chat', chat)
graph.add_edge(START, 'chat')
graph.add_edge('chat', END)

memory = MemorySaver()
chatbot = graph.compile(checkpointer=memory)
config = {"configurable": {"thread_id": "1"}}

# loop — stateful invoke
response = chatbot.invoke(
    {'messages': [HumanMessage(content=user_message)]},
    config=config
)
# Turn 1: saves [H1, AI1] @ thread_1
# Turn 2: loads [H1,AI1] + [H2] → "You're Theo!"
💡
Mental model: add_messages is the merge inside one run. MemorySaver + thread_id is the persistence across runs. You need both. Without thread_id, the checkpoint has no key — it’s like a database with no primary key.

1
It’s not the LLM that forgets
The LLM is stateless by design. You choose what you send: [H2] vs [H1,AI1,H2]. The bug was the caller sending only the last message.
2
add_messages ≠ persistence
Annotated[list, add_messages] merges correctly within one invoke. Across invokes you need a checkpointer.
3
Thread = conversation
Change thread_id → new conversation. Reuse it → continuation. For production, use SqliteSaver / PostgresSaver to survive restarts.
